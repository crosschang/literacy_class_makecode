# 개인정보 보안 블록코딩 교사용 가이드

## 1. 수업 개요

이 문서는 Minecraft Education MakeCode 튜토리얼 **「개인정보 보안 블록코딩」**을 수업할 때 선생님이 참고할 수 있는 운영 가이드입니다.

학생용 README는 학생이 블록을 따라 만드는 데 초점을 둡니다. 이 교사용 가이드는 수업 흐름, 지도 포인트, 완성 코드, 자주 발생하는 오류 해결을 정리합니다.

### 권장 대상

- 초등학교 4~6학년
- MakeCode 블록코딩을 1~2회 이상 경험한 학생
- 리스트, 조건문, 반복문을 처음 배우거나 복습하는 학생

### 권장 수업 시간

- 기본형: 40~45분
- 설명과 실습을 충분히 포함하는 경우: 60분
- 학생 개별 오류 점검까지 포함하는 경우: 80분

### 수업 목표

학생들이 개인정보 단서를 직접 정리하고, 문장 안에 개인정보가 포함되어 있는지 블록코딩으로 검사합니다.

학생들은 이 활동을 통해 다음 내용을 배웁니다.

- 개인정보 단서가 무엇인지 이해하기
- 리스트에 검사할 단어를 저장하기
- 채팅 명령어로 코드 실행하기
- 조건문으로 잘못된 번호 걸러내기
- 반복문으로 여러 단서를 차례대로 검사하기
- 문자열 안에 특정 단어가 들어 있는지 확인하기
- 개인정보를 함부로 공개하면 안 되는 이유 이해하기

## 2. 수업 전 준비

수업 전에 아래 항목을 확인해 주세요.

### Minecraft / MakeCode 준비

1. Minecraft Education 월드가 정상적으로 열리는지 확인합니다.
2. Code Builder가 정상적으로 실행되는지 확인합니다.
3. 학생용 MakeCode 튜토리얼 링크가 최신 버전인지 확인합니다.
4. 확장 패키지 버전이 최신인지 확인합니다.
5. 학생 계정으로 튜토리얼이 열리는지 테스트합니다.
6. 실행 버튼을 누른 뒤 `검사 1`, `검사 2`, `검사 6` 명령어가 정상 작동하는지 확인합니다.

### 확장 블록 확인

학생 화면에서 아래 커스텀 블록이 보이면 정상입니다.

- `검사문장모음`
- `검사할 리스트의 데이터 개수`
- `검사할 리스트의 n의 데이터 가져오기`
- `문장 안에 단서가 들어 있나요?`

### 개인정보 지도 주의

학생이 자신의 실제 개인정보를 예시로 쓰지 않도록 안내합니다.

권장 안내 문구:

> 오늘은 개인정보를 배우지만, 실제 여러분의 이름, 전화번호, 집 주소, 학교 밖 개인 정보는 쓰지 않습니다.  
> 수업에서는 예시 단어만 사용합니다.

## 3. 핵심 수업 구조

이 수업의 핵심 구조는 다음과 같습니다.

```text
검사할 문장 모음
→ 확장 블록 안에 준비되어 있음

개인정보단서 리스트
→ 학생이 직접 작성함

검사 명령어
→ 채팅창에 검사 1, 검사 2처럼 입력함

반복문
→ 개인정보단서 리스트를 하나씩 확인함

문자열 포함 검사
→ 검사할 문장 안에 단서가 들어 있는지 확인함
```

학생들이 이해해야 할 핵심은 이것입니다.

```text
문장 하나를 가져온다.
그 문장 안에 개인정보 단서가 있는지 하나씩 찾아본다.
하나라도 찾으면 개인정보가 포함되어 있을 수 있다고 알려준다.
```

## 4. 수업 진행 흐름

### 도입 5분

학생들에게 개인정보 단서의 의미를 설명합니다.

예시 질문:

- 사람을 알아볼 수 있게 만드는 말에는 무엇이 있을까요?
- 전화번호는 왜 조심해야 할까요?
- 학교와 학년이 함께 있으면 왜 더 조심해야 할까요?
- 이메일에 자주 들어가는 표시는 무엇일까요?

추천 단서:

```text
학교, 학년, 이름, 전화번호, 주소, 이메일, 010, @, .com
```

---

### Step 1~2: 개인정보단서 리스트 만들기

학생들이 직접 작성할 수 있는 부분입니다.

처음부터 모든 단서를 넣기 어려워하면 필수 5개만 먼저 쓰게 해도 됩니다.

필수 단서:

```text
학교, 학년, 이름, 전화번호, 주소
```

확장 단서:

```text
010, 아파트, 이메일, @, .com, 집, 번호
```

지도 포인트:

- 문자열은 반드시 따옴표 안에 넣습니다.
- 항목 사이에는 쉼표를 넣습니다.
- 실제 개인정보를 쓰지 않습니다.

---

### Step 3~6: 검사 명령어와 번호 확인

학생이 채팅창에 `검사 1`처럼 입력하면 코드가 실행됩니다.

번호가 잘못되었을 때는 안내 문장을 출력합니다.

지도 포인트:

- `num1`은 학생이 입력한 숫자입니다.
- `검사 1`이면 `num1`은 1입니다.
- `검사 100`처럼 없는 번호를 입력하면 안내 문장이 나와야 합니다.

주의:

```blocks
player.onChat("검사", function (num1) {})
```

`검사` 뒤에 공백이 있으면 실행이 꼬일 수 있습니다.

잘못된 예:

```blocks
player.onChat("검사 ", function (num1) {})
```

---

### Step 7~9: 검사할 문장 가져오기

학생이 입력한 번호에 맞는 문장을 확장 블록에서 가져옵니다.

지도 포인트:

- `CheckList.GetCheckList_Getdata()`는 검사할 문장 목록을 가져옵니다.
- `CheckList.GetCheckList_Sentence(..., num1)`은 해당 번호의 문장을 가져옵니다.
- 가져온 문장은 `검사할_문장` 변수에 저장합니다.

학생 설명 예시:

> 우리가 직접 문장을 다 적는 것이 아니라, 미리 준비된 문장 목록에서 번호에 맞는 문장을 가져오는 거예요.

---

### Step 10~13: 개인정보 단서 반복 검사

이 수업에서 가장 어려운 부분입니다.

반복문은 반드시 0부터 시작합니다.

```blocks
for (let 값 = 0; 값 <= CheckList.GetCheckList_Length(개인정보단서); 값++) {}
```

이유:

- 학생용 튜토리얼에서는 반복문을 0부터 시작합니다.
- 0번에서 가져온 빈 문자열은 확장 블록이 검사하지 않으므로
- 판정 결과에는 영향을 주지 않습니다.

지도 포인트:

```blocks
단서 = CheckList.GetCheckList_Sentence(개인정보단서, 값)
```

현재 번호의 개인정보 단서를 가져옵니다.

```blocks
if (CheckList.GetCheckList_Haskeyword(검사할_문장, 단서)) {}
```

검사할 문장 안에 현재 단서가 들어 있는지 확인합니다.

---

### Step 14~16: 결과 출력

반복 검사가 끝난 뒤 `발견됨` 값을 확인합니다.

- `발견됨 == true`이면 개인정보가 포함되어 있을 수 있다고 안내합니다.
- 아니면 개인정보 단서가 없다고 안내합니다.

지도 포인트:

`발견됨`은 스위치 같은 변수입니다.

```text
처음에는 false
단서를 하나라도 찾으면 true
마지막에 true인지 false인지 확인
```

## 5. 최종 완성 코드

학생 코드가 꼬였을 때는 아래 코드를 기준으로 확인해 주세요.

```blocks
let 개인정보단서: string[] = []

개인정보단서 = [
"학년",
"학교",
"전화번호",
"010",
"아파트",
"이름",
"이메일",
".com",
"@",
"주소",
"집",
"번호"
]

player.onChat("검사", function (num1) {
    if (num1 < 1 || num1 > CheckList.GetCheckList_Length(CheckList.GetCheckList_Getdata())) {
        player.say("1부터 " + CheckList.GetCheckList_Length(CheckList.GetCheckList_Getdata()) + "까지의 번호를 입력해 주세요.")
    } else {
        발견됨 = false
        검사할_문장 = CheckList.GetCheckList_Sentence(CheckList.GetCheckList_Getdata(), num1)
        player.say("검사할 문장 : " + 검사할_문장)

        for (let 값 = 0; 값 <= CheckList.GetCheckList_Length(개인정보단서); 값++) {
            단서 = CheckList.GetCheckList_Sentence(개인정보단서, 값)

            if (CheckList.GetCheckList_Haskeyword(검사할_문장, 단서)) {
                발견됨 = true
                player.say("개인정보 단서 발견 : " + 단서)
            }
        }

        if (발견됨 == true) {
            player.say("이 문장에는 개인정보가 포함되어 있을 수 있어요!")
        } else {
            player.say("이 문장에는 개인정보 단서가 없어요.")
        }
    }
})
```

## 7. 자주 발생하는 오류와 해결

| 문제 상황 | 원인 | 해결 방법 |
|---|---|---|
| `검사 1`을 입력해도 실행되지 않음 | 실행 버튼을 누르지 않았거나 `검사` 뒤에 공백이 있음 | 실행 버튼 확인, `player.onChat("검사", ...)`로 수정 |
| `개인정보 단서 발견 :`처럼 빈칸이 나옴 | 반복문이 0부터 시작함 | `값 = 1`부터 시작하도록 수정 |
| 모든 단서가 발견된 것처럼 나옴 | 단서 번호에 `num1`을 사용함 | `CheckList.GetCheckList_Sentence(개인정보단서, 값)` 사용 |
| 찾은 단서와 출력 단서가 다름 | `개인정보단서[값]` 직접 접근을 사용함 | `단서` 변수를 출력 |
| `string[]` 관련 오류가 남 | 리스트와 문자열 타입을 혼동함 | 리스트는 `string[]`, 문장 하나는 `string`인지 확인 |
| 블록이 회색 JavaScript처럼 보임 | `includes`, 배열 인덱스 등을 직접 사용함 | 커스텀 블록 `GetCheckList_Haskeyword` 사용 |
| 예전 코드가 계속 열림 | MakeCode 캐시 또는 튜토리얼 링크가 예전 버전임 | 확장 버전, GitHub 태그, Share 링크 확인 |
| 번호 안내가 이상하게 나옴 | 검사 문장 개수 블록이 잘못 연결됨 | `CheckList.GetCheckList_Length(CheckList.GetCheckList_Getdata())` 구조 확인 |

### Step 10 지도 포인트

학생용 튜토리얼에서는 MakeCode 블록 화면이 안정적으로 보이도록 반복문을 `0`부터 시작합니다.

```blocks
for (let 값 = 0; 값 <= CheckList.GetCheckList_Length(개인정보단서); 값++) {

}
```

논리적으로는 `1`부터 시작하는 방식도 가능하지만, MakeCode 튜토리얼에서는 `1`부터 시작하는 `for` 구문이 회색 JavaScript 블록처럼 보일 수 있습니다.

이 수업에서는 확장 블록 안에서 빈 단서 `""`는 검사하지 않도록 처리했기 때문에, `값 = 0`에서 빈 값이 들어가도 결과에는 영향을 주지 않습니다.

```blocks
if (word == "") {}
```

따라서 학생용 튜토리얼에서는 **블록 화면의 안정성**을 위해 `0`부터 시작하는 반복문을 사용합니다.

## 11. 수업 마무리 질문

## 12. 교사용 빠른 점검표

수업 직전에 아래만 확인해도 됩니다.

```text
□ 학생용 튜토리얼 링크가 최신인가?
□ 확장 패키지 버전이 최신인가?
□ Code Builder가 열리는가?
□ 실행 버튼을 눌렀는가?
```
